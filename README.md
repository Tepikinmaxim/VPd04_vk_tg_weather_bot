# VPd04_vk_weather

## Назначение

`OpenWeatherAPI.py` — синхронный клиент OpenWeatherMap для погодного бота VK.
Модуль получает текущую погоду, пятидневный прогноз с шагом три часа, данные о
загрязнении воздуха и выполняет прямое/обратное геокодирование. Тексты для
пользователя формируются на русском языке, а результат имеет стабильные
английские ключи для интеграции с ботом или другим приложением.

`weather_vk_bot/` — основной VK-бот на high-level `vkbottle`: Long Poll API,
кнопочное меню, FSM-состояния, геолокация, прогноз и расширенный режим с
качеством воздуха. Точка входа — `/main.py`.

`vk_bot.py` — прежний VK-бот на low-level `API` + `BotPolling`, сохранённый как
legacy. Он продолжает работать, но новый функционал развивается в
`weather_vk_bot/`.

## Возможности

- текущая погода по названию города или координатам;
- базовый и расширенный режимы: давление, видимость, восход/закат, качество
  воздуха;
- прогноз на пять дней с трёхчасовыми периодами; в CLI и VK-боте показывается
  по одному блоку на день на 12:00 MSK;
- определение населённого пункта по координатам с запасным вариантом, если
  обратное геокодирование недоступно;
- повторные запросы при сетевых ошибках и ответах `429`, `500`, `502`, `503`,
  `504` с задержками 1, 2 и 4 секунды;
- понятные исключения без раскрытия API-ключа;
- основной VK-бот на high-level `Bot` + `Message` + `BotLabeler`:
  FSM-состояния, кнопки, навигация и Long Poll API;
- красивое emoji-оформление текущей погоды, расширенного режима и прогноза;
- геолокация через нативную кнопку VK `Location` и ручной ввод координат;
- CLI-запуск для проверки текущей погоды, расширенного режима и прогноза;
- человекочитаемый вывод CLI, JSON по флагу `--json`, интерактивное меню из
  трёх вариантов и повторный ввод города в одном сеансе;
- legacy-бот на low-level `API` + `BotPolling` с прежним сценарием «город →
  режим».

## Соответствие требованиям сдачи

- Виртуальное окружение: `.venv/`; зависимости зафиксированы в
  `requirements.txt`.
- Секреты: `.env` читается через `python-dotenv`, добавлен в `.gitignore`;
  `.env.example` содержит только заглушки. API-ключи и токены не хранятся в
  коде и не выводятся в логи.
- API вынесен отдельно: `OpenWeatherAPI.py` отвечает за OpenWeatherMap,
  `weather_vk_bot/` — за VK, FSM, клавиатуры и форматирование.
- Long Poll: высокоуровневый `vkbottle.Bot`, запуск через `python main.py`;
  проверка доступа — `python main.py --check`.
- Кнопочные команды: «🌤 Погода сейчас», «📅 Прогноз 5 дней»,
  «📍 Геолокация», «🌫 Расширенный режим», «ℹ️ Помощь» — больше трёх.

## Требования

- Python 3.11+ (проект проверен на Python 3.14.2);
- `requests>=2.32,<3`;
- `python-dotenv>=1.0,<2`;
- `vkbottle>=4.11,<5`;
- `certifi>=2024.2.2` (CA-сертификаты для TLS-запросов VK);
- действующий API-ключ OpenWeatherMap;
- сообщество VK с включённым Long Poll API и ключ доступа сообщества.

## Настройка

Создайте `.env` на основе `.env.example` и заполните две переменные:

```dotenv
OPENWEATHER_API_KEY=your_openweather_api_key_here
VK_BOT_TOKEN=your_vk_community_token_here
```

В `.env.example` после `=` остаются нейтральные заглушки, чтобы было понятно,
что вставлять. В рабочем `.env` над каждой переменной есть комментарий с
назначением и местом получения значения; после `=` вставляется реальный секрет.
Файл `.env` загружается через `python-dotenv`, добавлен в `.gitignore` и не
должен попадать в репозиторий. API-ключ OpenWeather можно передать аргументом
`api_key` конструктору; токен VK передаётся только через `.env`.

Если ключ OpenWeather не найден, создание клиента завершится ошибкой
`OpenWeatherAPIError`. Если не задан `VK_BOT_TOKEN`, `main.py` выведет сообщение
с именем переменной и завершится с кодом `2`, не раскрывая секрет.
`VK_GROUP_ID` больше не используется: high-level `Bot` и legacy-бот определяют
сообщество по токену.

### Настройка сообщества VK для Long Poll

1. Создайте сообщество или используйте существующее и включите приём сообщений
   сообщества.
2. Откройте `Управление → Сообщения → Настройки для бота`, включите
   `Возможности ботов` и `Добавить кнопку «Начать»`, затем сохраните. При
   необходимости включите `Разрешать добавлять сообщество в чаты`.
3. Откройте `Управление → Дополнительно → Работа с API`.
4. На вкладке `Long Poll API` выберите `Включено` (бот использует Bots Long Poll
   API и `groups.getLongPollServer`).
5. В разделе `Bots Long Poll API → Типы событий` включите входящие сообщения
   (`message_new`).
6. Создайте ключ доступа сообщества с правом на работу с сообщениями
   (`messages`). Скопируйте его в `VK_BOT_TOKEN`.

Если `Возможности ботов` выключены, диалог с сообществом может не открываться,
кнопка «Начать» не появляется, а бот не получает события. Это настройка
сообщества, а не ошибка кода.

Long Poll не требует публичного HTTPS-адреса и Callback API: бот сам запрашивает
события у VK. Сообщество определяется по токену. Не публикуйте токен, не
передавайте его аргументом CLI и не добавляйте в логи.

Официальная документация по взаимодействию с VK:
<https://dev.vk.com/ru/api/bots/development/app-interaction>; Bots Long Poll
API: <https://vk.com/dev/bots_longpoll>.

## Использование

```python
from OpenWeatherAPI import OpenWeatherAPI, OpenWeatherAPIError

with OpenWeatherAPI() as api:
    try:
        weather = api.get_weather_by_city("Москва")
        extended = api.get_weather_by_city("Москва", extended=True)
        forecast = api.get_forecast_by_city("Москва", extended=True)
        by_coords = api.get_weather_by_coordinates(
            55.7558,
            37.6173,
            extended=True,
        )
    except OpenWeatherAPIError as exc:
        print(f"Ошибка OpenWeather: {exc}")
```

Дополнительные параметры клиента:

```python
api = OpenWeatherAPI(
    api_key="...",       # если не используется .env
    timeout=10.0,        # таймаут одного HTTP-запроса
    max_retries=3,       # число повторов
    session=None,        # своя requests.Session при необходимости
)
```

Клиент поддерживает контекстный менеджер и закрывает только собственную
HTTP-сессию; переданная снаружи `session` не закрывается.

## Запуск VK-бота

Основная точка входа — корневой `main.py`; реализация находится в
`weather_vk_bot/`. Бот работает через Long Poll API высокоуровневого
`vkbottle.Bot`, без Callback API и публичного сервера:

```sh
.venv/bin/python main.py
```

Проверить `VK_BOT_TOKEN` и доступ к сообществу без запуска Long Poll:

```sh
.venv/bin/python main.py --check
```

Сценарий общения:

1. `/start` показывает главное меню с кнопками `🌤 Погода сейчас`,
   `📅 Прогноз 5 дней`, `📍 Геолокация`, `🌫 Расширенный режим`, `ℹ️ Помощь`.
2. Для погоды или прогноза бот запрашивает город и отвечает emoji-блоком.
3. В расширенном режиме добавляются давление, видимость, рассвет/закат,
   AQI, загрязнители и краткий анализ воздуха.
4. Для геолокации используется нативная кнопка `Location`; если она
   недоступна, отправьте координаты в формате `55.7558, 37.6173` или
   `55.7558 37.6173`.
5. `⬅️ Назад` и `🏠 Главное меню` возвращают в начало.

FSM-состояния и последний город хранятся только в памяти процесса и
сбрасываются при перезапуске. Настройка `--log-level` принимает `DEBUG`,
`INFO`, `WARNING` или `ERROR`.

### Legacy low-level бот

Прежняя реализация `vk_bot.py` сохранена для обратной совместимости и не
участвует в новом сценарии. Она также работает без `VK_GROUP_ID` и определяет
сообщество по токену:

```sh
.venv/bin/python vk_bot.py
.venv/bin/python vk_bot.py --check
```

## Запуск из командной строки

Основная точка входа — `cli.py`; модуль `OpenWeatherAPI.py` также можно
запускать напрямую. API-ключ берётся из `.env` или переменной окружения; флаг
для передачи ключа намеренно не предусмотрен, чтобы он не попадал в историю
команд.

```sh
python cli.py Москва
python cli.py Москва --extended
python cli.py Москва --forecast
python cli.py Москва --forecast --extended
python cli.py --coords 55.7558 37.6173
python cli.py --coords 55.7558 37.6173 --extended
python cli.py Москва --extended --json
python cli.py --help
```

Те же команды работают с `python OpenWeatherAPI.py`.

Если запустить `python cli.py` без аргументов в интерактивном терминале,
программа попросит ввести город и предложит выбрать вариант:

```sh
python cli.py
# Введите город: Москва
# Выберите вариант: РАСШИРЕННАЯ ПОГОДА-1 / ТЕКУЩАЯ ПОГОДА-2 / ПРОГНОЗ НА 5 ДНЕЙ-3: 3
```

Пункт `1` включает расширенный режим, `2` или пустой ответ оставляет базовый,
`3` показывает прогноз на пять дней. Флаг `--extended` работает без
дополнительного вопроса.

При выводе прогноза в текстовом режиме показывается один блок на каждый день,
время среза — 12:00 MSK (UTC+3). OpenWeatherMap присылает `dt_txt` в UTC,
поэтому выбирается период 09:00 UTC и его время пересчитывается в MSK.
Заголовок прогноза явно сообщает это правило пользователю. В режиме `--json`
прогноз остаётся полным трёхчасовым списком, а поле `дата_время` содержит
исходное время UTC, как его вернул API.

После вывода результата CLI предлагает продолжить работу:

```sh
# Введите город — 1 или выйти из приложения — 2: 1
# Введите город: Сочи
# Выберите вариант: РАСШИРЕННАЯ ПОГОДА-1 / ТЕКУЩАЯ ПОГОДА-2 / ПРОГНОЗ НА 5 ДНЕЙ-3: 2
```

Ответ `1` возвращает к вводу города и меню вариантов, `2` или пустой ответ
завершают приложение. Интерактивное меню показывается при запуске без города и
`--coords`; разовые команды с аргументами и режим `--json` завершаются после
вывода результата.

- `--extended` добавляет давление, видимость, восход/закат и качество воздуха;
- `--forecast` запрашивает прогноз на пять дней (только по городу);
- `--coords LAT LON` запрашивает текущую погоду по координатам;
- `--json` выводит JSON вместо текста;
- одновременно город и `--coords`, а также `--coords` с `--forecast` запрещены.

По умолчанию CLI выводит структурированный текст: разделы, русские названия
параметров и значения с единицами измерения.

```text
Местоположение
  Название — Сочи
  Широта   — 43.5854823
  ...

Погода
  Описание    — ясно
  Температура — 15.04 °C
  Влажность   — 83 %
  ...
```

Флаг `--json` сохраняет машиночитаемый вывод: JSON в UTF-8 с отступами и
русскими ключами (`местоположение`, `погода`, `температура_c`, `давление_гпа`,
`качество_воздуха`). Библиотека при этом по-прежнему возвращает стабильные
английские ключи, описанные в разделе «Формат результата библиотеки». Ошибки
API выводятся в `stderr`, код возврата — `1`; ошибки аргументов — код `2`.
Прогноз по координатам пока не поддерживается.

## Формат результата библиотеки

Методы возвращают английские ключи. CLI по умолчанию показывает русские
подписи, а с `--json` переводит ключи на русский.

### Текущая погода

- `location`: `name`, `lat`, `lon`, `country`, `state`;
- `weather`: `description`, `condition`, `temperature_c`, `feels_like_c`,
  `temp_min_c`, `temp_max_c`, `humidity_percent`, `wind_speed_ms`,
  `clouds_percent`.

В расширенном режиме в `weather` добавляются `pressure_hpa`, `sea_level_hpa`,
`ground_level_hpa`, `visibility_m`, `visibility_km`; появляются блоки `sun`
(`sunrise_unix`, `sunrise_utc`, `sunset_unix`, `sunset_utc`) и `air_quality`.

### Качество воздуха

- `aqi_index` — индекс AQI от OpenWeatherMap (1–5);
- `aqi_label`, `aqi_category` — категория AQI от OpenWeatherMap;
- `overall_aqi_index`, `overall_category`, `overall_label` — категория,
  рассчитанная по концентрациям загрязнителей;
- `pollutants` — значения, единицы и категории по каждому веществу;
- `exceeded_pollutants`, `exceeded_pollutant_names` — вещества выше безопасного
  порога;
- `human_summary` и `details` — готовые русские тексты для ответа пользователю.

### Прогноз

Результат содержит `location` и список `forecast`. Каждый период включает
`datetime` (время UTC в формате API), `description`, `temperature_c`,
`humidity_percent`, `pressure_hpa`, `clouds_percent`, `wind_speed_ms`,
`precipitation_probability`, `precipitation_probability_percent`.
В расширенном режиме добавляются `sun` и `air_quality`. Текстовый вывод CLI
оставляет один период на день — на 12:00 MSK.

## Ошибки

- `OpenWeatherAPIError` — базовая ошибка модуля (неверные данные, ключ,
  параметры или HTTP-ответ);
- `CityNotFoundError` — город не найден;
- `APIConnectionError` — не удалось связаться с OpenWeatherMap.

## Ограничения

- клиент синхронный и блокирует вызывающий поток на время HTTP-запросов; в
  VK-боте запросы выполняются через `asyncio.to_thread`;
- прогноз ограничен возможностями OpenWeatherMap: пять дней, шаг три часа;
  текстовый вывод показывает срез на 12:00 MSK по одному блоку в день;
- без действующего API-ключа и доступа к интернету запросы не выполняются;
- кеширование ответов не реализовано;
- в CLI прогноз доступен только по городу; прогноза по координатам нет;
- состояние диалога основного и legacy VK-бота хранится в памяти и сбрасывается
  при перезапуске;
- для VK-бота нужен включённый Long Poll API и ключ сообщества; без реального
  токена проверяется только конфигурация и тесты с подменой VK API;
- нативная геолокация зависит от разрешения пользователя и возможностей клиента
  VK; ручной ввод координат остаётся fallback;
- legacy `vk_bot.py` не участвует в новом сценарии и сохраняется отдельно;
- качество русских описаний зависит от переводов в API OpenWeatherMap.

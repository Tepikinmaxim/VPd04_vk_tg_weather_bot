# VPd04_vk_weather

## Назначение

`OpenWeatherAPI.py` — синхронный клиент OpenWeatherMap для погодных ботов VK и
Telegram. Модуль получает текущую погоду, пятидневный прогноз, данные о
загрязнении воздуха и выполняет прямое/обратное геокодирование. Погодный CLI
вынесен в пакет `cli/` и запускается через `python -m cli`. В текстовом выводе
показывается один прогноз на каждый из пяти дней — на 12:00 MSK. Тексты
для пользователя формируются на русском языке, а результат имеет стабильные
английские ключи для интеграции с ботом или другим приложением.

`weather_vk_bot/` — основной VK-бот на high-level `vkbottle`: Long Poll API,
кнопочное меню, FSM-состояния, запоминание города, сравнение погоды двух
городов, геолокация, прогноз и расширенный режим с качеством воздуха. При
запуске бот проверяет доступные настройки сообщества VK. После разрешения
сообщений бот сам отправляет меню в личный диалог без `/start`. Точка входа —
`/main.py`.

`weather_tg_bot/` — Telegram-бот на `aiogram 3` с тем же набором функций:
текущая погода, прогноз, расширенный режим, сравнение, геолокация, смена
города и справка. Работает через long polling, состояние хранится в памяти.
Точка входа — `telegram_main.py`.

`weather_core/` — общий нейтральный слой для VK и Telegram: API-сервис,
форматтеры, тексты, кнопки, сравнение городов, координаты и разбиение длинных
сообщений.

`vk_bot.py` — прежний VK-бот на low-level `API` + `BotPolling`, сохранённый как
legacy. Он продолжает работать, но новый функционал развивается в
`weather_vk_bot/`.

## Возможности

- текущая погода по названию города или координатам;
- базовый и расширенный режимы: давление, видимость, восход/закат, качество
  воздуха;
- прогноз на пять дней; в CLI и VK-боте показывается по одному прогнозу на день
  на 12:00 MSK;
- определение населённого пункта по координатам с запасным вариантом, если
  обратное геокодирование недоступно;
- повторные запросы при сетевых ошибках и ответах `429`, `500`, `502`, `503`,
  `504` с задержками 1, 2 и 4 секунды;
- понятные исключения без раскрытия API-ключа;
- основной VK-бот на high-level `Bot` + `Message` + `BotLabeler`:
  FSM-состояния, кнопки, автоматический возврат в меню и Long Poll API;
- запоминание последнего города и повторное использование без нового запроса;
- русские названия городов из `local_names.ru` OpenWeatherMap, если они есть;
- смена сохранённого города с возвратом в главное меню;
- сравнение текущей погоды в двух городах с разницей температуры, ощущаемой
  температуры, влажности, ветра и облачности;
- строка «Актуально на» с локальным временем устройства в текущей погоде,
  расширенном режиме и сравнении; в пятидневном прогнозе её нет;
- автоматическое приветствие и меню после события `message_allow`, без `/start`;
- стартовая проверка прав токена, Long Poll API и событий `message_new`,
  `message_allow`;
- Telegram-бот на `aiogram 3`: long polling, reply-клавиатура, те же погодные
  сценарии и автоматическое распознавание координат;
- `--check` для Telegram проверяет токен, вебхук и наличие ключа OpenWeatherMap;
- красивое emoji-оформление текущей погоды, расширенного режима и прогноза;
- геолокация через нативную кнопку VK `Location` и ручной ввод координат;
  сообщение с координатами автоматически запускает этот сценарий из любого
  состояния;
- CLI-запуск для проверки текущей погоды, расширенного режима и прогноза;
- человекочитаемый вывод CLI, JSON по флагу `--json`, интерактивное меню из
  трёх вариантов и повторный ввод города в одном сеансе;
- legacy-бот на low-level `API` + `BotPolling` с прежним сценарием «город →
  режим».

## Соответствие требованиям сдачи

- Виртуальное окружение: `.venv/`; зависимости зафиксированы в
  `requirements.txt`.
- Секреты: `.env` читается через `python-dotenv`, добавлен в `.gitignore`;
  `.env.example` содержит только заглушки. API-ключи и токены не хранятся в
  коде и не выводятся в логи.
- API вынесен отдельно: `OpenWeatherAPI.py` отвечает за OpenWeatherMap,
  `weather_core/` — общий слой, `weather_vk_bot/` и `weather_tg_bot/` — адаптеры
  платформ, FSM, клавиатуры и форматирование.
- Long Poll: высокоуровневый `vkbottle.Bot`, запуск через `python main.py`;
  проверка доступа и настроек — `python main.py --check`.
- Кнопочные команды: «🌤 Погода сейчас», «📅 Прогноз 5 дней»,
  «📊 Сравнить погоду», «📍 Геолокация», «🌫 Расширенный режим»,
  «🏙 Сменить город», «ℹ️ Помощь» — больше трёх.

## Настройка

Создайте `.env` на основе `.env.example` и заполните переменные:

```dotenv
OPENWEATHER_API_KEY=your_openweather_api_key_here
VK_BOT_TOKEN=your_vk_community_token_here
TELEGRAM_BOT_TOKEN=your_telegram_bot_token_here
```

`VK_BOT_TOKEN` нужен только VK-боту, `TELEGRAM_BOT_TOKEN` — только Telegram.
Оба бота используют общий `OPENWEATHER_API_KEY`.

В `.env.example` после `=` остаются нейтральные заглушки, чтобы было понятно,
что вставлять. В рабочем `.env` над каждой переменной есть комментарий с
назначением и местом получения значения; после `=` вставляется реальный секрет.
Файл `.env` загружается через `python-dotenv`, добавлен в `.gitignore` и не
должен попадать в репозиторий. API-ключ OpenWeather можно передать аргументом
`api_key` конструктору; токен VK передаётся только через `.env`.

Если ключ OpenWeather не найден, создание клиента завершится ошибкой
`OpenWeatherAPIError`. Если не задан `VK_BOT_TOKEN`, `main.py` выведет сообщение
с именем переменной и завершится с кодом `2`, не раскрывая секрет.
`VK_GROUP_ID` больше не используется: high-level `Bot` и legacy-бот определяют
сообщество по токену.

### Настройка сообщества VK для приёма сообщений

Бот использует Bots Long Poll API: публичный HTTPS-сервер и Callback API не
нужны. Все настройки выполняются в интерфейсе сообщества VK, код при этом не
меняется.

#### 1. Включите сообщения сообщества

1. Создайте сообщество или откройте существующее, в котором будет работать бот.
2. Перейдите в `Управление → Сообщения`.
3. Включите сообщения сообщества. После этого у пользователей появляется
   кнопка для отправки сообщения, а у администраторов — входящие диалоги.
4. Проверьте с личного аккаунта, что диалог открывается кнопкой
   «Написать сообщение» или «Начать». Не отправляйте тестовое сообщение от
   имени сообщества.

#### 2. Включите возможности бота

1. В сообществе откройте `Управление → Сообщения → Настройки для бота`.
2. Включите:
   - `Возможности ботов`;
   - `Добавить кнопку «Начать»`.
3. При необходимости включите `Разрешать добавлять сообщество в чаты`.
4. Сохраните настройки.

`Возможности ботов` и кнопка «Начать» должны быть включены до запуска бота.
Если они выключены, диалог может не открываться, а события не поступать.

#### 3. Включите Long Poll API и нужные события

1. Откройте `Управление → Дополнительно → Работа с API`.
2. На вкладке `Long Poll API` выберите `Включено`.
3. В разделе `Bots Long Poll API` (или `Long Poll API`) → `Типы событий`
   включите:
   - `Входящие сообщения` (`message_new`) — команды и кнопки;
   - `Разрешение на отправку сообщений` (`message_allow`) — автоматическое
     приветствие без `/start`.
4. Сохраните изменения.

`message_event` нужен только для callback-кнопок, если вы добавите их позже.
VK не присылает отдельное событие при простом открытии диалога: бот может
написать первым только после того, как пользователь разрешил сообщения.
Повторное открытие уже разрешённого диалога события не создаёт; в этом случае
меню по-прежнему открывается командой `/start`.

#### 4. Создайте ключ доступа сообщества

1. В `Управление → Дополнительно → Работа с API` откройте `Ключи доступа`.
2. Создайте ключ для сообщества с правом `messages` (работа с сообщениями).
3. Скопируйте ключ в `.env`:

   ```dotenv
   VK_BOT_TOKEN=...
   ```

4. `VK_GROUP_ID` не нужен: сообщество определяется по токену.

Ключ сообщества — секрет. Не передавайте его аргументом CLI, не публикуйте и
не добавляйте в логи. `.env` уже добавлен в `.gitignore`.

#### 5. Запустите и проверьте

```sh
.venv/bin/python main.py --check
.venv/bin/python main.py
```

`--check` проверяет токен, право `messages`, Long Poll API и события
`message_new`, `message_allow` без запуска Long Poll. Проверка «Возможности
ботов» и кнопки «Начать» доступна только в интерфейсе VK: при запуске бот
выводит напоминание о ней. Для проверки входящих сообщений можно отправить
`/start` с личного аккаунта. Успешный приём подтверждают:

- в терминале или логе появляется `Получено сообщение`;
- в истории сообщества входящее сообщение имеет `out=0`;
- бот отвечает и показывает кнопки.

Сообщения с `out=1` и `from_id=-<id сообщества>` — исходящие от имени
сообщества. Бот не получает их как входящие, поэтому для проверки нужно писать
с личного аккаунта, а не в режиме «От имени сообщества».

#### Если сообщения не приходят

| Симптом | Что проверить |
|---|---|
| Нет кнопки «Написать сообщение» или «Начать» | Включены ли сообщения сообщества и `Возможности ботов`; доступно ли сообщество аккаунту. |
| Диалог открывается, но бот молчит | Включён ли Long Poll API и события `message_new`, `message_allow`; запущен ли `python main.py`. |
| Нет приветствия без `/start` | Пользователь уже разрешал сообщения раньше, поэтому `message_allow` не пришёл; отправьте `/start`. |
| Нужно проверить автостарт заново | Используйте аккаунт, который ещё не разрешал сообщения, либо сначала запретите и снова разрешите сообщения сообщества. |
| Бот отвечает, но кнопок нет | Включены ли `Возможности ботов` в `Управление → Сообщения → Настройки для бота`; проверьте отчёт `main.py --check`. |
| Ответы бота дублируются | Запущено несколько экземпляров `main.py`. Проверьте `ps -axo pid,command \| grep '[m]ain.py'`; при обычном запуске бот остановит старые экземпляры автоматически. |
| `--check` сообщает об ошибке доступа | Используется ли ключ сообщества, а не пользовательский токен; не истёк ли ключ. |
| В истории только `out=1` | Сообщение отправлено от имени сообщества; отправьте `/start` с личного аккаунта. |
| Настройки изменены, но поведение прежнее | Перезапустите бота после изменения `.env` или настроек VK. |

Long Poll не требует публичного HTTPS-адреса и Callback API: бот сам запрашивает
события у VK. Официальная документация:
<https://dev.vk.com/ru/api/bots/development/app-interaction>; Bots Long Poll API:
<https://vk.com/dev/bots_longpoll>. Справка VK по сообщениям сообщества:
<https://vk.com/faq18341>.

## Использование

```python
from OpenWeatherAPI import OpenWeatherAPI, OpenWeatherAPIError

with OpenWeatherAPI() as api:
    try:
        weather = api.get_weather_by_city("Москва")
        extended = api.get_weather_by_city("Москва", extended=True)
        forecast = api.get_forecast_by_city("Москва", extended=True)
        by_coords = api.get_weather_by_coordinates(
            55.7558,
            37.6173,
            extended=True,
        )
    except OpenWeatherAPIError as exc:
        print(f"Ошибка OpenWeather: {exc}")
```

Дополнительные параметры клиента:

```python
api = OpenWeatherAPI(
    api_key="...",       # если не используется .env
    timeout=10.0,        # таймаут одного HTTP-запроса
    max_retries=3,       # число повторов
    session=None,        # своя requests.Session при необходимости
)
```

Клиент поддерживает контекстный менеджер и закрывает только собственную
HTTP-сессию; переданная снаружи `session` не закрывается.

## Запуск VK-бота

Основная точка входа — корневой `main.py`; реализация находится в
`weather_vk_bot/`. Бот работает через Long Poll API высокоуровневого
`vkbottle.Bot`, без Callback API и публичного сервера:

```sh
.venv/bin/python main.py
```

Проверить `VK_BOT_TOKEN`, права и настройки Long Poll без запуска бота:

```sh
.venv/bin/python main.py --check
```

Одновременно должен работать только один экземпляр. При запуске бот:

- захватывает lock `.vkbottle/vk_bot.lock`;
- находит другие процессы `main.py`, запущенные из каталога проекта;
- автоматически останавливает старые экземпляры без lock (сначала `SIGTERM`,
  затем `SIGKILL`);
- не трогает `main.py --check`, процессы из других каталогов и активный
  экземпляр, который уже удерживает lock.

Если lock уже удерживает другой экземпляр с этой же версией кода, новый запуск
завершится с кодом `1` и сообщением с PID, не останавливая активный бот.
Отключить автоостановку старых процессов можно флагом `--no-kill-stale` — тогда
запуск завершится с ошибкой, если найдены другие экземпляры.

Проверить вручную, сколько экземпляров запущено:

```sh
ps -axo pid,command | grep '[m]ain.py'
```

Сценарий общения:

1. При первом открытии личного диалога после разрешения сообщений бот сам
   отправляет приветствие «Погодный эксперт» со списком возможностей и
   кнопками `🌤 Погода сейчас`, `📅 Прогноз 5 дней`, `📊 Сравнить погоду`,
   `📍 Геолокация`, `🌫 Расширенный режим`, `🏙 Сменить город`, `ℹ️ Помощь`;
   `/start` не обязателен. Если событие `message_allow` уже было получено
   раньше, отправьте `/start`.
2. Если город уже сохранён, погода, прогноз и расширенный режим выполняются
   сразу; иначе бот запрашивает город и запоминает его.
3. `🏙 Сменить город` запрашивает новое название, сохраняет его и возвращает в
   главное меню с подписью `🏙 Текущий город: ...`.
4. `📊 Сравнить погоду` использует текущий город как первый и запрашивает
   второй. Если города ещё нет, бот запрашивает оба. Второй город должен
   отличаться от первого: пример в приглашении не повторяет первый город, а
   повторный ввод возвращает к запросу второго города. Более тёплый город
   показывается первым, затем идёт `📊 Итог сравнения` с городом и разницей по
   температуре, ощущаемой температуре, влажности, ветру и облачности. При
   равенстве пишется `одинаково`, при отсутствии данных — `нет данных`.
5. В расширенном режиме добавляются давление, видимость, рассвет/закат,
   AQI, загрязнители и краткий анализ воздуха.
6. Для геолокации используется нативная кнопка `Location`; если она
   недоступна, отправьте координаты в формате `55.7558, 37.6173` или
   `55.7558 37.6173`. Координаты можно отправить в любой момент, не открывая
   `📍 Геолокация`: бот распознаёт пару чисел и сразу запускает геосценарий.
   Полученный населённый пункт сохраняется как текущий.
7. `ℹ️ Помощь` повторяет то же приветствие «Погодный эксперт» со списком
   возможностей, что и `/start`.
8. После показа результата бот сразу возвращает в главное меню: клавиатура
   корня прикреплена к сообщению с результатом, отдельного сообщения меню нет.
   Для прерывания ввода можно отправить `/cancel`.

FSM-состояния и последний город хранятся только в памяти процесса и
сбрасываются при перезапуске. Настройка `--log-level` принимает `DEBUG`,
`INFO`, `WARNING` или `ERROR`.

## Запуск Telegram-бота

1. Создайте бота через `@BotFather` командой `/newbot`.
2. Скопируйте токен в `.env`:

   ```dotenv
   TELEGRAM_BOT_TOKEN=...
   ```

3. Проверьте токен и настройки без запуска polling:

   ```sh
   .venv/bin/python telegram_main.py --check
   ```

4. Запустите бота:

   ```sh
   .venv/bin/python telegram_main.py
   ```

Бот работает через long polling, публичный HTTPS-сервер и вебхук не нужны.
В личном чате отправьте `/start`; появится reply-клавиатура с теми же
разделами, что у VK-бота. Координаты вида `54.989347, 73.368221` можно
отправить в любой момент — бот сам запустит геосценарий.

`--check` проверяет токен через `getMe`, предупреждает об установленном
вебхуке (он мешает polling) и проверяет наличие `OPENWEATHER_API_KEY`.
Геокнопка Telegram работает в личных чатах; в группах доступен ручной ввод
координат. Состояние диалога и сохранённый город хранятся в памяти и
сбрасываются при перезапуске. Одновременно должен работать один polling-
экземпляр.

## Запуск из командной строки

Основная точка входа — пакет `cli/`; запуск выполняется через `python -m cli`.
API-ключ берётся из `.env` или переменной окружения; флаг для передачи ключа
намеренно не предусмотрен, чтобы он не попадал в историю команд.

```sh
python -m cli Москва
python -m cli Москва --extended
python -m cli Москва --forecast
python -m cli Москва --forecast --extended
python -m cli --coords 55.7558 37.6173
python -m cli --coords 55.7558 37.6173 --extended
python -m cli Москва --extended --json
python -m cli --help
```

`OpenWeatherAPI.py` остаётся API-модулем и больше не запускает CLI напрямую.

Если запустить `python -m cli` без аргументов в интерактивном терминале,
программа попросит ввести город и предложит выбрать вариант:

```sh
python -m cli
# Введите город: Москва
# Выберите вариант: РАСШИРЕННАЯ ПОГОДА-1 / ТЕКУЩАЯ ПОГОДА-2 / ПРОГНОЗ НА 5 ДНЕЙ-3: 3
```

Пункт `1` включает расширенный режим, `2` или пустой ответ оставляет базовый,
`3` показывает прогноз на пять дней. Флаг `--extended` работает без
дополнительного вопроса.

При выводе прогноза в текстовом режиме показывается один прогноз на каждый
день, время — 12:00 MSK (UTC+3). OpenWeatherMap присылает `dt_txt` в UTC,
поэтому выбирается период 09:00 UTC и его время пересчитывается в MSK.
Заголовок прогноза явно сообщает это правило пользователю. В режиме `--json`
прогноз остаётся исходным списком периодов, а поле `дата_время` содержит
исходное время UTC, как его вернул API.

После вывода результата CLI предлагает продолжить работу:

```sh
# Введите город — 1 или выйти из приложения — 2: 1
# Введите город: Сочи
# Выберите вариант: РАСШИРЕННАЯ ПОГОДА-1 / ТЕКУЩАЯ ПОГОДА-2 / ПРОГНОЗ НА 5 ДНЕЙ-3: 2
```

Ответ `1` возвращает к вводу города и меню вариантов, `2` или пустой ответ
завершают приложение. Интерактивное меню показывается при запуске без города и
`--coords`; разовые команды с аргументами и режим `--json` завершаются после
вывода результата.

- `--extended` добавляет давление, видимость, восход/закат и качество воздуха;
- `--forecast` запрашивает прогноз на пять дней (только по городу);
- `--coords LAT LON` запрашивает текущую погоду по координатам;
- `--json` выводит JSON вместо текста;
- одновременно город и `--coords`, а также `--coords` с `--forecast` запрещены.

По умолчанию CLI выводит структурированный текст: разделы, русские названия
параметров и значения с единицами измерения.

```text
Местоположение
  Название — Сочи
  Широта   — 43.5854823
  ...

  Актуально на 27.10.2026, 12:35.

Погода
  Описание    — ясно
  Температура — 15.04 °C
  Влажность   — 83 %
  ...
```

Флаг `--json` сохраняет машиночитаемый вывод: JSON в UTF-8 с отступами и
русскими ключами (`местоположение`, `погода`, `температура_c`, `давление_гпа`,
`качество_воздуха`). Библиотека при этом по-прежнему возвращает стабильные
английские ключи, описанные в разделе «Формат результата библиотеки». Ошибки
API выводятся в `stderr`, код возврата — `1`; ошибки аргументов — код `2`.
Прогноз по координатам пока не поддерживается.

## Формат результата библиотеки

Методы возвращают английские ключи. CLI по умолчанию показывает русские
подписи, а с `--json` переводит ключи на русский.

### Текущая погода

- `location`: `name` (русское `local_names.ru`, если API его вернул), `lat`,
  `lon`, `country`, `state`;
- `weather`: `description`, `condition`, `temperature_c`, `feels_like_c`,
  `temp_min_c`, `temp_max_c`, `humidity_percent`, `wind_speed_ms`,
  `clouds_percent`.

В расширенном режиме в `weather` добавляются `pressure_hpa`, `sea_level_hpa`,
`ground_level_hpa`, `visibility_m`, `visibility_km`; появляются блоки `sun`
(`sunrise_unix`, `sunrise_utc`, `sunset_unix`, `sunset_utc`) и `air_quality`.

### Качество воздуха

- `aqi_index` — индекс AQI от OpenWeatherMap (1–5);
- `aqi_label`, `aqi_category` — категория AQI от OpenWeatherMap;
- `overall_aqi_index`, `overall_category`, `overall_label` — категория,
  рассчитанная по концентрациям загрязнителей;
- `pollutants` — значения, единицы и категории по каждому веществу;
- `exceeded_pollutants`, `exceeded_pollutant_names` — вещества выше безопасного
  порога;
- `human_summary` и `details` — готовые русские тексты для ответа пользователю.

### Прогноз

Результат содержит `location` и список `forecast`. Каждый период включает
`datetime` (время UTC в формате API), `description`, `temperature_c`,
`humidity_percent`, `pressure_hpa`, `clouds_percent`, `wind_speed_ms`,
`precipitation_probability`, `precipitation_probability_percent`.
В расширенном режиме добавляются `sun` и `air_quality`. Текстовый вывод CLI
оставляет один период на день — на 12:00 MSK.

## Ошибки

- `OpenWeatherAPIError` — базовая ошибка модуля (неверные данные, ключ,
  параметры или HTTP-ответ);
- `CityNotFoundError` — город не найден;
- `APIConnectionError` — не удалось связаться с OpenWeatherMap.

## Проверка

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Ожидаемый результат: `Ran 208 tests ... OK`. Тесты ботов не выполняют реальных
запросов к VK и Telegram: API и загрузчик погоды подменяются, конфигурация
проверяется без сети.

Проверка конфигурации без запуска ботов:

```sh
.venv/bin/python main.py --check
.venv/bin/python telegram_main.py --check
.venv/bin/python vk_bot.py --check   # legacy
```

`main.py --check` печатает отчёт по сообществу: право `messages`, Long Poll
API, события `message_new`, `message_allow`, напоминание вручную проверить
«Возможности ботов» и список других запущенных экземпляров. При критической
ошибке команда завершается с кодом `1`. `--check` не останавливает процессы;
автоостановка выполняется при обычном запуске.

`telegram_main.py --check` проверяет токен через `getMe`, предупреждает об
установленном вебхуке и проверяет наличие `OPENWEATHER_API_KEY`.

Проверка запуска бота без токена:

```sh
.venv/bin/python main.py
# Ошибка: Не задан VK_BOT_TOKEN. Откройте .env и вставьте значение в строку VK_BOT_TOKEN=.
```

## Ограничения

- клиент синхронный и блокирует вызывающий поток на время HTTP-запросов; в
  VK-боте запросы выполняются через `asyncio.to_thread`;
- прогноз ограничен возможностями OpenWeatherMap: пять дней; текстовый вывод
  показывает срез на 12:00 MSK по одному прогнозу в день;
- без действующего API-ключа и доступа к интернету запросы не выполняются;
- кеширование ответов не реализовано;
- в CLI прогноз доступен только по городу; прогноза по координатам нет;
- состояние диалога, последний город и сравнение основного и legacy VK-бота
  хранятся в памяти и сбрасываются при перезапуске;
- для VK-бота нужен включённый Long Poll API и ключ сообщества; без реального
  токена проверяется только конфигурация и тесты с подменой VK API;
- «Возможности ботов» и кнопка «Начать» не проверяются через API сообщества:
  `main.py --check` только напоминает проверить их в интерфейсе VK. Если бот
  отвечает, но кнопок не видно, включите «Возможности ботов»;
- нативная геолокация зависит от разрешения пользователя и возможностей клиента
  VK; ручной ввод координат остаётся fallback;
- в Telegram геокнопка работает в личных чатах; в группах остаётся ручной ввод
  координат;
- Telegram-бот использует long polling и память процесса: состояние
  сбрасывается при перезапуске, одновременно должен работать один экземпляр;
- если `api.telegram.org` недоступен в сети, нужен системный VPN или прокси;
  встроенная настройка прокси пока не добавлена;
- legacy `vk_bot.py` не участвует в новом сценарии и сохраняется отдельно;
- качество русских описаний зависит от переводов в API OpenWeatherMap;
- русское название города берётся из `local_names.ru`; если OpenWeatherMap не
  вернул перевод, показывается английское `name`.

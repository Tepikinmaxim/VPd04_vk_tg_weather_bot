# План: Telegram-бот с функционалом VK-бота

**Проект:** VPd04_vk_tg_weather_bot
**Дата:** 27.10.2026  
**Статус:** реализовано и запущено 27.10.2026

## Цель

Добавить в проект Telegram-бота с тем же погодным функционалом, что у
high-level VK-бота: текущая погода, расширенный режим, прогноз на 5 дней,
сравнение двух городов, геолокация, сохранение города, справка и понятные
ошибки. VK-бот и погодный CLI должны продолжать работать без изменений
поведения.

## Принятые решения

- Библиотека: `aiogram 3` (проверено на 3.31.0).
- Python: 3.14.2; aiogram поддерживает `>=3.10,<3.15`.
- HTTP-клиент: установленный `aiohttp 3.14.5` удовлетворяет требованию
  aiogram `>=3.9,<3.15`, понижать версию не нужно.
- Общий код: вынести нейтральные части в `weather_core/`, чтобы VK и Telegram
  использовали один форматтер, сервис, тексты и проверки.
- Чаты: основной сценарий — личные чаты.
- Состояние: в памяти, как у VK; при перезапуске сбрасывается.
- Транспорт: long polling, без вебхука и публичного HTTPS-сервера.
- Токен BotFather у пользователя есть; токен хранится только в `.env`.

## Соответствие VK и Telegram

| VK | Telegram |
|---|---|
| Bots Long Poll API | polling через `Dispatcher.start_polling` |
| `VK_BOT_TOKEN` | `TELEGRAM_BOT_TOKEN` от BotFather |
| `message_allow` + `/start` | `/start` (аналога `message_allow` нет) |
| Reply-клавиатура VK | `ReplyKeyboardMarkup` |
| Вложение `Location` | `KeyboardButton(request_location=True)` и `message.location` |
| Лимит сообщения 4000 | лимит 4096, общий `split_message` |
| `BuiltinStateDispenser` + `CtxStorage` | `MemoryStorage` + `FSMContext` |
| Проверки прав сообщества | `getMe()` и `getWebhookInfo()` |
| legacy `vk_bot.py` | не переносится |

## Этапы

### Этап 1. Общее ядро `weather_core`

1. Создать пакет `weather_core/`.
2. Перенести нейтральные сервисы:
   - `weather_vk_bot/services/formatter.py` → `weather_core/services/formatter.py`;
   - `weather_vk_bot/services/weather_service.py` →
     `weather_core/services/weather_service.py`.
3. Вынести из `weather_vk_bot/handlers/common.py` тексты в
   `weather_core/texts.py`.
4. Вынести подписи кнопок в `weather_core/buttons.py`.
5. Вынести из `weather_vk_bot/handlers/comparison.py` общую логику сравнения
   в `weather_core/comparison.py`.
6. Вынести разбор и проверку координат в `weather_core/geo.py`.
7. Вынести `split_message` в `weather_core/message.py`.
8. Обновить импорты VK-бота и тестов.
9. Сохранить прежние значения `BotState` и тексты.

**Проверка:** полный набор VK-тестов (`165 tests`) проходит; VK-бот
перезапускается и работает.

### Этап 2. Каркас Telegram-бота

1. Добавить `aiogram>=3.31,<4` в `requirements.txt`.
2. Создать `telegram_main.py` с вызовом `weather_tg_bot.main.main()`.
3. Создать `weather_tg_bot/main.py`:
   - загрузка `.env`;
   - проверка `TELEGRAM_BOT_TOKEN` и `OPENWEATHER_API_KEY`;
   - флаги `--check` и `--log-level`;
   - коды возврата `0`, `1`, `2`;
   - сообщения об ошибках без раскрытия секретов.
4. Создать `weather_tg_bot/bot.py`:
   - `Bot` с `DefaultBotProperties(parse_mode=None)`;
   - `Dispatcher(storage=MemoryStorage())`;
   - `Router`, регистрация handlers;
   - логирование входящих сообщений без текста;
   - обработчик неожиданных ошибок.
5. Реализовать `--check`:
   - `getMe()` — токен и имя бота;
   - `getWebhookInfo()` — предупреждение, если вебхук установлен;
   - наличие `OPENWEATHER_API_KEY`;
   - человекочитаемый отчёт в терминале.

### Этап 3. Клавиатуры и состояния

1. Главная reply-клавиатура с теми же подписями:
   - `🌤 Погода сейчас`
   - `📅 Прогноз 5 дней`
   - `📊 Сравнить погоду`
   - `🌫 Расширенный режим`
   - `📍 Геолокация`
   - `🏙 Сменить город`
   - `ℹ️ Помощь`
2. Параметры клавиатуры: `resize_keyboard=True`,
   `is_persistent=True`.
3. Геоклавиатура:
   - `📍 Отправить геопозицию` с `request_location=True`;
   - `✍️ Ввести координаты`;
   - `⬅️ В меню` — потому что reply-клавиатура заменяет главное меню.
4. Состояния `TgState`:
   - главное меню;
   - ожидание города;
   - ожидание города для прогноза;
   - ожидание геопозиции;
   - ожидание города для расширенного режима;
   - ожидание нового города;
   - ожидание первого города сравнения;
   - ожидание второго города сравнения.
5. Данные пользователя в `FSMContext`: `last_city`, `last_mode`,
   `first_city`.

### Этап 4. Handlers и сценарии

1. `/start` — приветствие `HELP_TEXT` и главное меню.
2. `/help`, `help`, `помощь` — справка и меню.
3. `/cancel`, `cancel`, `отмена` — возврат в главное меню.
4. «Погода сейчас»:
   - использовать сохранённый город;
   - иначе запросить город и перейти в состояние ожидания.
5. «Прогноз 5 дней»:
   - использовать сохранённый город;
   - иначе запросить город;
   - вызвать общий `format_forecast`.
6. «Расширенный режим»:
   - использовать сохранённый город;
   - иначе запросить город;
   - вызвать общий `format_current(extended=True)`.
7. «Сравнить погоду»:
   - первый город из сохранённого или запросить;
   - второй город запросить;
   - отклонить дубль по названию до запроса API;
   - после геокодинга проверить совпадение координат;
   - использовать общий `format_comparison`.
8. «Геолокация»:
   - принять `message.location`;
   - принять координаты текстом `55.7558, 37.6173` или
     `55.7558 37.6173`;
   - проверить диапазоны;
   - вызвать `get_by_coordinates`.
9. «Сменить город»:
   - запросить новый город;
   - сохранить его после ввода;
   - вернуть в главное меню.
10. Fallback:
    - пустой текст — показать меню;
    - неизвестный текст — показать меню и подсказку.
11. Ошибки:
    - город не найден;
    - сеть/API недоступны;
    - неверные координаты;
    - неожиданная ошибка.
12. Отправка длинных сообщений:
    - лимит 4096;
    - клавиатура только на последней части.

### Этап 5. Особенности Telegram

- `parse_mode=None`, чтобы не экранировать `°C`, `%`, `м/с` и emoji.
- Reply-клавиатура вместо inline: нажатие присылает текст кнопки.
- Геокнопка `request_location` работает в личных чатах; в группах останется
  ручной ввод координат.
- Состояние в `MemoryStorage`; после перезапуска город нужно ввести заново.
- Одновременно должен работать только один polling-экземпляр, иначе Telegram
  вернёт конфликт.
- VK-бот и Telegram-бот запускаются отдельными процессами.

## Риски и ограничения

- Перенос общего ядра затрагивает импорты VK — главный риск; страховка:
  полный прогон 165 тестов и перезапуск VK-бота.
- В Telegram нет аналога `message_allow`: приветствие только по `/start`.
- Геокнопка Telegram работает в личных чатах; в группах — ручные координаты.
- Состояние хранится в памяти и сбрасывается при перезапуске.
- Для живого запуска нужен токен BotFather в `.env`.
- Второй polling-экземпляр вызовет конфликт Telegram.
- Групповой режим отдельно не оптимизируется.
